# 安全模型

NetPanel 保存着能登录你所有交换机的密码，所以它自己的安全边界需要说清楚。本文说明：什么被存在哪里、怎么保护、什么是它**不**防的。

## 面板账号

- 面板有**自己的管理员账号**（只有一个；多用户和权限分级不在当前范围内），和交换机的账号无关。
- 密码只存 scrypt 哈希（N=2¹⁴、r=8、p=1），至少 8 个字符。账号不存在和密码错误时耗时相同。
- 登录限速：每个来源地址每分钟最多 10 次尝试。

## 登录态

- 登录后发一个随机的会话令牌（32 字节），放在 Cookie `netpanel_session` 里：`HttpOnly`（页面的脚本读不到）、`SameSite=Strict`（其它网站发起的请求不会带上）、12 小时无操作后过期。
- 会话只存在内存里：**面板重启后需要重新登录**，改密码后其它浏览器上的登录态立即失效。
- 未登录时只有 `GET /api/status`（回答"要不要初始化、登没登录"）和登录 / 初始化 / 退出接口可用，不泄露设备地址、账号等信息。

## 防跨站请求伪造（CSRF）

- 所有会改动状态的请求都必须带自定义请求头 `X-Requested-With: netpanel`。浏览器里的跨站表单发不出自定义请求头。
- 请求带 `Origin` 时，它必须与 `Host` 同源。
- Cookie 是 `SameSite=Strict`；接口不返回任何 CORS 头。
- 危险操作（重启、恢复出厂、修改 IP、还原……）在接口层还要求 `confirm: true`，恢复出厂要求 `confirmText: "RESET"`——这两样只能由页面的脚本在用户确认之后放进请求体。

## 响应头

每个响应都带：

```
Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
X-Frame-Options: DENY
```

前端不拼接 HTML 字符串、不加载任何第三方脚本，交换机返回的文本（设备描述、VLAN 名、MAC 搜索结果……）都经文本节点进入页面。`Cache-Control: no-cache` 让浏览器每次都重新取前端文件，升级面板后不会拿旧脚本配新接口。

## 交换机的密码

- 添加设备时填的密码**只在那一刻经过浏览器一次**（所以别在不可信的网络上打开面板），之后保存在数据目录的 `devices.json` 里，是 **AES-256-GCM** 的密文。
- 密钥是 `secret.key` 里的 32 个随机字节，与数据放在一起，用设备 id 作为附加认证数据——把某台设备的密文挪到另一台设备上也解不出来。
- 密文被改动时解密会失败（不会返回错误的明文）。
- 密码解密后只在面板进程的内存里使用，用于建立到交换机的连接。**接口从不把密码返回给浏览器**（设备对象里只有 `hasSecret: true`），日志和错误信息里也不会出现它。
- **`secret.key` 和 `devices.json` 要一起备份、一起恢复。** 只有 `devices.json` 而没有密钥，已保存的密码就解不回来（在界面里重新输入即可）。

## 指标接口

`/metrics` 需要 Bearer 令牌（24 个随机字节），令牌与提交的值用常量时间比较。它和面板登录态无关：Prometheus 不需要、也不应该持有面板的账号。指标里有设备名称，请按敏感信息对待。在设置页可以随时重新生成令牌，旧的立即失效。

## 命令行

- 密码优先从环境变量 `NETPANEL_PASSWORD` 读，避免留在 shell 历史和进程列表里。
- 危险操作在非交互运行时必须显式加 `--yes`；参数先过校验，不合法的请求不会发到交换机。
- `--url` 模式不往磁盘写任何东西。

## 它不防什么

请把这些当作使用前提：

1. **交换机自己的管理接口是明文 HTTP。** 面板登录交换机时，账号、密码和会话 Cookie 在局域网里是明文传输的——这是设备决定的，面板改变不了。面板能做的只是不把密码进一步扩散。
2. **面板本身默认只监听 `127.0.0.1`。** 要让局域网里的其它电脑访问，需要把监听地址改成 `0.0.0.0`，这时面板的登录和"添加设备时填写的交换机密码"在你的网络里也是明文的。**只在你信任的网络里这么做**；要跨公网访问，请放在带 TLS 的反向代理之后，或者通过 VPN。
3. **能读到数据目录的人能解密所有设备密码。** 密钥和数据存放在一起，这是"面板重启后能无人值守地采集"的代价。请用操作系统的文件权限保护 `data/` 目录（面板以 0600 创建密钥文件；Windows 上依赖目录的访问控制）。
4. **实验性的 `tplink-json` 适配器不校验交换机的 TLS 证书**（这类交换机默认是 HTTPS + 自签证书）。它只应该用在局域网内。
5. **没有审计日志。** 谁在什么时候改了什么配置，目前不记录。
6. 面板以你的交换机账号的身份操作，权限与你自己登录设备相同。它不会（也不能）绕过交换机上的任何限制。
